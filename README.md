# PaperMate · 开源论文搭子（Academic Writing Agent）

把 academic-writing skill（学术论文写作决策 + 审查知识库）包装成的**独立 Web 应用**——带能力界面、结构化输入、词面检测与**大模型逐条判读**，覆盖论文从选题到投稿返修的完整生命周期。

> 与「资料库工作台」方案的本质区别：本应用是**独立前后端**，后端直连 DeepSeek / Anthropic / 萤算 等大模型，真正完成 298 条需语义判读规则的逐条判读，而不是"复制 Prompt 到对话"的半自动方案。

## 一、能做什么（七大能力）

| 阶段 | 能帮用户做什么 | 核心产出 |
|---|---|---|
| 1. 选题定位 | 判断"做什么方向、值不值得做" | 研究问题 + gap 论证 |
| 1b.（可选）选题雷达 | 跑 OpenAlex 全球发文趋势 + AI 三维评估（维度随学科主线与层级变化） | 候选题目 + 三维打分 + 趋势判读 |
| 2. 研究设计评审 | 校验识别策略、内生性、抽样、对照组 | 设计缺陷清单 + 修正方向 |
| 3. 初稿写作引导 | 按引言/方法/结果/讨论逐段给框架 | 逐段框架 + 正反例句 |
| 4. 引用格式规范 | 四套体系（IEEE/APA/GB7714/脚注）选型与逐条修正 | 规范引用 |
| 5. 投稿前审查 | 结构自检 + 词面检测 + 大模型逐条判读 | 三层风险清单 |
| 6. 投稿与返修 | 投稿包清单 + rebuttal 结构 | 投稿包 + rebuttal |
| 7. 一键成稿（学术小白） | 选题→定题→设计→大纲→分章成稿→自检，一次跑完 | 英文工作稿（Word/Markdown/LaTeX 可导出）+ 自检报告 |

> **选题雷达是选题的常规一步**：默认展开，跑 OpenAlex 发文趋势 + AI 三维评估。它仍以独立扩展包形式挂载（便于整包卸载、便于自证没改原文），但对使用者不再需要「先展开才生效」。卸载后 skill 与 v1.2.0 原包一字不差。

## 二、快速开始

### 方式 0：部署到云服务器（1.3.0 新增）

需要多人通过浏览器访问、或想挂在自己域名上时，用这一条：

```bash
unzip PaperMate-1.3.0-cloud-src.zip && cd academic-writing-agent
cp .env.cloud.example .env
python3 -c "import secrets;print(secrets.token_urlsafe(24))"   # 生成访问口令
vi .env                                                        # 填口令与 API Key
docker compose up -d --build
```

不想用 Docker 就用 `sudo bash deploy/install.sh`（裸机 systemd 一键装）。
完整手册见 **[deploy/DEPLOY.md](deploy/DEPLOY.md)**，含访问控制三模式、
Nginx 反代配置、数据备份与 12 条验收清单。

> 1.2.8 本身就是网页版，但只监听本机 `127.0.0.1`、状态全在内存、无访问控制。
> 1.3.0 补上了服务端模式、口令鉴权与状态落盘，桌面版行为不变。

### 方式 A：安装包（推荐，不需要装 Python）

双击 `PaperMate-Setup-1.3.0.exe`，按向导走完即可。装完桌面会有「开源论文搭子」图标。

安装程序会**先体检再安装**，不会让你装完才发现打不开：

| 检查项 | 不满足时 |
|---|---|
| 系统版本（需 Windows 10+） | 直接拦下，说明原因 |
| 系统位数（需 64 位） | 直接拦下（32 位系统跑不了内置的 64 位运行时） |
| 磁盘空间（需 800 MB） | 直接拦下，报出实际可用空间 |
| 用户目录可写 | 直接拦下，提示换安装位置或找 IT |
| 是否已有旧版在运行 | 拦下，提示先关闭 |
| 内存（建议 2 GB+） | 仅提示，不阻断 |
| VC++ 运行库 | 仅提示，给出补装链接（影响 PDF 解析等可选功能） |
| 8000 端口 | 仅提示，程序会自动顺延到 8001/8002 |

装完直接启动，浏览器自动打开。**不需要 Python，不需要 pip，不需要联网装依赖。**

**装在哪儿（两个目录，别搞混）**

| 目录 | 放什么 | 卸载时 |
|---|---|---|
| `%LOCALAPPDATA%\Programs\PaperMate` | 程序本体（约 143 MB） | 删除 |
| `%LOCALAPPDATA%\PaperMate` | **你的数据**：上传的文件、成稿记录、`.env`（API Key）、检索缓存 | **保留** |

程序与数据分离，是为了让你升级或重装程序时**不丢稿子、不用重填 Key**。
卸载后想彻底清除，手动删掉 `%LOCALAPPDATA%\PaperMate` 即可。

> 为什么不用管理员权限：学术用户多是学生和老师，学校机房、单位电脑常常
> 拿不到管理员。默认装进当前用户目录，全程不弹 UAC。

### 装不上 / 起不来时的三条兜底

1. **先自检**：`python env_check.py` —— 逐项列出 Python 版本、必需依赖、可选组件、目录写权限、端口占用、API Key 状态，缺什么写什么，并给出修复命令。加 `--install` 会缺什么装什么。
2. **依赖装不上**（国内最常见）：换镜像重试
   ```bash
   python -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
   ```
   `start.bat` / `start.sh` 内部已自动依次尝试「默认源 → 清华 → 阿里云」，三个都失败才会停。
3. **端口被占用**：不用改配置。再启动一次会自动顺延到 8001/8002 并把实际地址打在窗口里；若 8000 上已经跑着一个 PaperMate，它会提示「已经在运行」并直接打开浏览器，而不是起第二个实例（两个实例的任务列表不共享，会让人以为「没反应」）。

**可选组件**（缺了不影响主流程，只是对应格式用不了）：

| 组件 | 装了能做什么 | 没装怎么办 |
|---|---|---|
| LibreOffice | 直接解析 `.doc`（老 Word）、读 `.xls` / `.ods` 数据 | 在 Word / Excel 里另存为 `.docx` / `.xlsx` |
| pandas | 直接读 `.dta` / `.sav` / `.parquet` 数据 | 在 Stata / SPSS / R 里导出 csv |
| openpyxl | 读 `.xlsx` 数据画像 | 已列为**必需依赖**，正常安装不会缺 |

> 前端渲染库（marked + MathJax 完整版）已内置在 `static/vendor/`，断网也能渲染表格与公式；页面不引用任何 CDN、在线字体。
>
> 解析老式 `.doc`（OLE 二进制）需要本机装有 **LibreOffice**（未装时请在 Word 里另存为 `.docx`）；`.docx`、`.md`、`.tex`、`.pdf` 无需额外软件。Word「另存为网页」得到的 `.doc` 其实是 HTML，不需要 LibreOffice，直接解析。

### 模型接入（只接三家）

| 方式 | 接口地址 | 模型 ID | 协议 / 说明 |
|---|---|---|---|
| DeepSeek 官方 | `https://api.deepseek.com` | `deepseek-chat` / `deepseek-v4-pro` / `deepseek-flash` | OpenAI 兼容，直连；chat 为稳定别名，v4-pro 推理更强、flash 更快 |
| Anthropic 官方 | `https://api.anthropic.com`（不带 `/v1`） | `claude-sonnet-4-5` / `claude-haiku-4-5` / `claude-opus-4-1` | 原生 Messages API：`x-api-key` 头 + `POST /v1/messages`，system 独立字段，`max_tokens` 必填 |
| 萤算 Lumda（聚合） | `https://api.lumdatech.com/api/v1` | `deepseek-v4-pro` / `deepseek-flash` | OpenAI 兼容，一个 key 调多家模型，低至 6 折起，星际直连 |

刻意不设「自定义中转」入口：地址填错时程序自动纠正，比让用户自己猜路径更可靠。设置面板里选服务商会自动填好地址、协议与模型，点「测试连接」探活（DeepSeek / 萤算走 `GET /models`，Anthropic 走 `GET /v1/models`，都不产生 token 费用）。

**地址填错会自动纠正**：把官网域名 `www.lumdatech.com` 当接口地址填是常见错误，请求会打到 Nginx 的 `/chat/completions` 被返回 **405 Not Allowed**。程序会把 `lumdatech.com` / `www.` / `api.` 一律收敛到 `https://api.lumdatech.com/api/v1`；Anthropic 同样处理（`anthropic.com` / `www.` / `claude.ai` → `https://api.anthropic.com`，误粘的 `/v1`、`/v1/messages` 自动剥掉），并在错误信息里写明纠正结果。

> 推广：萤算搭子平台（Lumda）为本项目推荐的模型通道，注册链接带 UTM 来源标记；本站不代收费用、不抽成，价格以平台实时页面为准。

## 三、架构（四层）

```
┌─ 前端（浏览器 SPA）──── 能力首页 + 七大能力导航 + 结构化输入 + 结果可视化 + 多轮追问
├─ 后端（Python FastAPI）── server.py + engine.py + llm.py + oneshot.py
├─ 规则层（原样复用）──── skill/ 目录：rules.yaml(393条) + detectors.yaml(95条) + references/ + 两个原生脚本
└─ LLM 层（OpenAI 兼容）── DeepSeek 逐条判读 298 条需人工的规则
```

关键点：

- **词面检测 100% 复用 skill 原生脚本**：`engine.py` 直接 import skill 自带的 `score.py` / `check_structure.py`，不重写、不复刻，与官方脚本输出完全一致（已用 39 份构造样稿回归验证：0 越界）。
- **大模型逐条判读**：`llm.py` 把需人工判读的规则按章节分组、分批（每批 10 条）交给大模型，对照每条规则的 `signal` 判读，输出三层风险清单（硬伤/建议/可选）+ 出处 + 改法。
- **多轮追问**：后端维护会话，可连续追问"为什么判这条""怎么改"（选题阶段不挂追问框，以导出交付为主）。
- **规则升级即同步**：规则文件以独立目录 `skill/` 挂载，升级 skill 时替换该目录即可，无需改代码。

### 输入输出格式（格式增强）

论文里真正费事的不是文字，而是表格、图片与公式。本应用在**输入解析**与**输出渲染/导出**两侧都做了处理：

| 环节 | 支持 |
|---|---|
| 稿件上传 | `.docx` / `.doc` / `.md` / `.markdown` / `.txt` / `.tex` / `.latex` / `.pdf` / `.html`（另兼容 `.rtf`、MHTML） |
| 格式识别 | **按文件内容判断，不只看扩展名**：Word「另存为网页」的 `.doc` 实际是 HTML、投稿系统导出的 `.docx` 可能是 RTF/HTML，都会被正确识别并解析；纯 ZIP 里没有 `word/document.xml` 会明确报错而不是静默失败 |
| 数据文件 | `.csv` / `.tsv` / `.txt` / `.xlsx` / `.xlsm` / `.xls` / `.ods` / `.json`；**可一次选多份**（主表 + 附表）。`xls`/`ods` 经本机 LibreOffice 转换，`dta`/`sav`/`parquet` 有 pandas 才能读（否则给导出指引）。多工作表自动挑最像数据表的一页，无表头自动编号，重名列自动加后缀 |
| 粘贴 | 从 Word / Excel / 网页粘贴的表格自动转 GFM 表格；截图直接落图并插入引用；上下标、粗体保留 |
| 解析保真 | Word 表格→Markdown 表格（含合并单元格）；Word 图片→抽取到 `uploads/`；Word 公式（OMML）→LaTeX；真正的二进制 `.doc` 经 LibreOffice 转 `.docx`（失败时降级为纯文本并提示）；LaTeX 原文保留并附章节大纲；Word-HTML 的重复标题（`## 摘要` + `#### 摘要`）自动去重 |
| 结果渲染 | GFM 表格（表头/隔行/横向滚动）、LaTeX 公式（MathJax **完整版**（2.2 MB）本地内置，`$..$`、`$$..$$`、`\(..\)`、裸 `\begin{equation}` 均可，`\boldsymbol`/`\operatorname`/`\tag` 等扩展已含）、图片（点击放大）、嵌套列表、代码块、引用 |
| 导出 | Markdown（`.md`）、Word（`.docx`，真表格 + 跨页表头 + **原生可编辑公式 OMML**）、LaTeX（`.tex`，`ctexart` 可直接 Overleaf 编译；含图片时自动打包 zip） |

> 结构自检补充说明：skill 的章节正则要求「方法/结果/讨论」等关键词紧跟标题行首，中文论文常用的复合标题（「数据与研究设计」「实证结果」「结论与讨论」）会被漏判。应用层做了**展示层补充识别**（不改 skill 文件、不改变任何规则命中），界面会注明哪几项是补充识别的结果。

> 渲染引擎本地内置（`static/vendor/`），不依赖外网 CDN，断网可用。文字金额如 `$50` 不会被误判成公式。

## 五、API 接口

| 接口 | 说明 |
|---|---|
| `GET /api/meta` | 学科主线/规则统计/期刊清单等元数据（含 `access` 访问模式） |
| `GET /api/health` | 探活（容器 healthcheck 用）；报版本、访问模式、数据目录 |
| `POST /api/auth/login` | 口令登录，下发签名 Cookie（`private` 模式直接放行） |
| `POST /api/auth/logout` | 退出登录，清除 Cookie |
| `GET /api/auth/status` | 当前是否已登录、是否 BYOK（前端据此渲染） |

## 六、一键成稿（学术小白）

> ⚠️ **先说最要紧的一条：AI 生成内容带水印，严禁直接使用。**
> 产出的全部文本都是 AI 生成内容，导出或转存的副本可能带可见/不可见的 AI 标记，转 PDF、截图、复制粘贴都去不掉。带标记的稿件投稿会被判为 AI 代写。
> **只能当写作骨架**：逐段用自己的语言重写，`[TBD: ...]` 填真实数据，`[CITE: ...]` 换成可核实文献，最终稿必须是你自己写出的文本。
> 界面上四处都有警示（页面顶部红色块、能力边界条目、成稿结果区、导出文件头），不必担心漏看。

给「知道想研究什么、但不知道怎么落成一篇英文论文」的人用：先在选题页把题定下来，再填几个选项，系统自动跑完七步，产出一篇结构合规、**引用可核实**的**工作稿**。

**第 0 步（人工）：先去「选题」用雷达定题。** 选题牵涉作者自己的判断——这个方向熟不熟、数据拿不拿得到、导师与审稿人认不认——所以这一步**不自动完成、也不自动回填**。流程是：选题页跑雷达（OpenAlex 趋势 + 3 个候选 + 三维打分）→ 你挑一个或改成自己的 → 点「复制题目」→ 回来粘到「已定题目」。

- 填了「已定题目」：第 1 步只做**题目体检**（可证伪？变量可见？范围是否过大？因果表述是否过强？），题目原样保留，**不另生成候选**；第 2 步也不再让模型重定一次题。
- **粘过来的题名是中文也没关系**：离开输入框会自动调模型译成学术英文题名（术语用标准译法，保留 Evidence from X / A Case Study of X 这类设计标记，不添加原题没有的方法与地域），译完在下方显示原题与「撤销」；也可以点输入框右侧「译为英文」手动触发。开始成稿时若题名仍是中文，还会在开跑前再译一次，日志里会写「题目已自动译为英文」。
- 未填：第 1 步会生成 3 个候选——但那是模型替你选，前置检查里会标「注意」，建议先回选题页评估。

**数据文件（可选，可多选）**：可上传 `csv / tsv / txt / xlsx / xlsm / xls / ods / json`，一次可以选多份（主表 + 附表，最多 8 份）。只读**结构**——列名、类型、缺失率、数值列的 min/max/mean/sd、二值列 1 的占比、文本列的平均长度，每列最多 3 个示例值（疑似姓名/手机/邮箱列自动脱敏）；**行级数据不发给模型，也不保存在服务端**（只存这份画像，点「移除」即删）。

上传后不只是"记下变量名"，还会：

- **判结构**：面板（含实体列、时间列、期数、是否平衡）/ 时间序列 / 截面 / 文本语料 / 普通表格；
- **认方法族**：DiD（处理变量 + 时期变量同存）、IV、RDD、生存分析、二分类预测、实验分组、模型评测指标、临床变量……
- **给主线建议**：由结构反推学科主线（如「面板 + DiD → 定量实证」），并列出依据；不一致时给你一个「用这个主线」按钮，**不点就不改你的选择**。开跑前的「① 前置条件检查」还会再比对一次，不一致会标黄。
- **进提示词**：第 3 步研究设计会明确写出「检测到面板：firm_id × year，40 实体 × 5 期」，并要求模型若采用别的识别策略就说明理由；第 5 步方法/结果章按画像里的真实变量名写，ID 列禁止当回归变量。

**数据不全怎么办（体检 + 找数据源 / 代下载，但正文不替你补数）**

上传后会做一次**数据体检**，直接说「按你这份数据，哪些分析做不了」：样本量（低于 30 行标阻断）、可分析变量够不够、关键变量缺失率（>40% 阻断、15%–40% 提醒）、面板期数（不足 3 期做不了双向固定效应/DiD）、时序长度（不足 20 期做不了单位根与协整）、数值变量是否几乎没有变异、多份文件能否按实体键连上。

体检结果三处可见：上传后就在数据卡里、开跑前的「① 前置条件检查」里、第 7 步 `07_check.md` 的「数据体检」表；阻断项会自动写进「投稿前必须处理」，也会进第 3 步的提示词，要求模型不许用「样本已清洗」这类话盖住缺口。

缺的数据点「查可用数据源」，按题目给线索，并对**白名单公开源**自动代下载：

| 缺什么 | 去哪儿 | 给到什么 |
|---|---|---|
| 国别宏观面板 | 世界银行 WDI | 按题目关键词命中指标（人均 GDP、研发投入、碳排放、互联网普及率…），给 `data.worldbank.org` 页面 + **自动代下载**到 `_sources/` |
| 论文复现数据包 | Zenodo、Harvard Dataverse | 真检索结果，带 DOI，**自动代下载**文件（>50MB 只给链接） |
| 中国宏观分省 | 国家统计局·国家数据 | 网页取数步骤（实测脚本直连会 403，所以只给入口，**不代下载**） |
| 微观/企业级 | CFPS、CGSS、CHARLS、CSMAR、Wind、ESG | 入口 + 申请/订阅方式 + 引用格式（授权/付费，**不代下载**） |

**代下载只碰白名单公开源，且落盘后不解析、不核对口径、不写回正文。** 跨源数据口径（单位、样本期、统计口径变更）一旦错配，错数进表比留空更危险。`[TBD: ...]` 始终是正文里唯一的占位方式。

「数据状态」现在有五档：

| 档位 | 结果章写法 | 额外动作 |
|---|---|---|
| 无数据 | 分析框架 + 表格骨架 + `[TBD: ...]` | — |
| **无数据，帮我找数据源** | 同「无数据」 | 自动检索 + **代下载白名单公开源**到 `_sources/`，落盘成 `03b_sources.md` |
| **演示模式** | 同「无数据」（正文仍 `[TBD]`） | 代下载公开源 + 另产 `demo_preview.md`（模拟值仅排版预览） |
| 部分数据 | 已有部分写实、缺的占位 | — |
| 已有真实数据 | 按真实分析写 | — |

「帮我找数据源」选中后不用再点按钮，系统会在第 3 步研究设计前自动检索一次（题名含企业/上市公司这类微观主体时，优先给 CSMAR、CFPS 等授权库入口，世行宏观面板只作兜底并标注适用条件；已上传数据表则按体检里缺的那类数据定向检索），结果落盘成 `03b_sources.md`，并在 `07_check.md` 里列成「可用的数据源线索」+ 一条取数待办。代下载的文件落到任务目录 `_sources/`，**未经解析与核对**，请先检查口径再上传。

「演示模式」额外产一份 `demo_preview.md`：正文仍用 `[TBD: ...]` 占位，演示稿把占位换成带 `*` 的模拟值、文件头大字标注 `SIMULATED DATA — LAYOUT PREVIEW ONLY, NOT FOR SUBMISSION`，仅供预览排版效果，**绝不可投稿**。模拟值不会出现在 `manuscript.md`、文献装配或自检里。

这两档**都不改变结果章正文的写法**——正文仍然只有表格骨架和 `[TBD: ...]`，模拟值只活在 `demo_preview.md`。检索失败也不会阻断成稿，会退成内置白名单入口。

格式支持上，`xls / ods` 用本机 LibreOffice 转 xlsx 再读（不需要额外装 Python 包）；`dta / sav / parquet` 在装了 pandas 的环境里能直接读，否则会明确提示「导出为 csv 或 xlsx」而不是给一句"不支持"。

| 步骤 | 做什么 | 产物 |
|---|---|---|
| 1 选题与候选 | **有已定题目** → 题目体检 + 落位（不换题）；**没有** → 生成英文检索式 → OpenAlex 趋势 → 3 个候选 + 三维打分 | `01_topic.md` |
| 2 定题 | 定稿题目、一句话研究问题、关键词、三条贡献、positioning；作者自定题目时直接沿用，不再重定 | `02_chosen.md` |
| 3 研究设计 | 识别策略、数据与样本、变量定义表、2–3 个 LaTeX 模型式、稳健性清单；数据状态选「帮我找数据源」时附可核实的数据源清单 | `03_design.md`（+ `03b_sources.md`） |
| 4 大纲与字数分配 | 按体裁给出各节要点 + 图表清单；字数由本地计划锁定，不让模型乱配 | `04_outline.md` |
| 5 分章成稿 | 逐节写作，写完全文再写摘要；结果章按数据状态决定写法（演示模式另产 `demo_preview.md`） | `05_draft.md` |
| 6 文献装配 | 先分流（数据源 / 点名文献 / 普通），再检索 → 白名单校验 → 按引用体系著录并替换 | `06_refs.md`、`manuscript.md` |
| 7 自检与体检 | 复用 skill 原生词面检测 + 结构检查，出缺陷清单与待办 | `07_check.md` |

**三条硬约束（写进提示词，不靠自觉）**：

1. **不编数据**：任何未知数值写成 `[TBD: 具体要填什么]`，宁可留空也不虚构。数据状态为「无数据」时，结果章只写分析框架 + 模型设定式 + 表格骨架。唯一的例外是「演示模式」的 `demo_preview.md`——模拟值只出现在这份独立文件里（带 `*` + SIMULATED 水印），绝不进正文。
2. **不造文献**：写作时引用处只写 `[CITE: 需要什么样的来源]`；第 6 步用 OpenAlex 真实检索把它换成带 DOI 的记录（白名单剔除仓储/预印本、无 DOI、年份异常与类型不符），检索不到就保留占位并写明原因——任何情况下都不编造作者与年份。
3. **英文优先**：规则库 393 条全部源自英文经典教材与国际期刊规范（Booth / Creswell / Graff / Zobel / Day & Gastel / Angrist & Pischke / Gelman / Pearl / NASEM），95 个检测器为英文正则 + 中文别名。**中文是受限通道**：政策建议、研究局限、中图分类号等国内刊惯例不在库内，界面与报告都会明确提示。
4. **AI 生成内容带水印，禁止直接使用**：一键成稿产出的一切文本都是 AI 生成内容，平台导出或转存的副本可能带可见或不可见的 AI 标记（水印 / 隐写标识 / 元数据），且**无法通过转 PDF、截图、复制粘贴去除**。带标记的稿件投稿会被期刊 AI 检测判为代写。因此：页面顶部、能力边界、成稿结果区都有红色警示；导出 docx / md / tex 时后端会在文件头**强制嵌入**警示（`ai_generated: true`），前端本地导出的 md 同样带警示；tex 走注释形式，不影响排版。正确用法只有一种——当写作骨架，逐段用自己的语言重写。

**使用方式**：`导航 → 一键成稿` → 粘贴已定题目（唯一必填项，不填无法开始）→ ① 前置条件检查（先看阻断项与章节字数计划）→ ② 开始一键成稿。执行中可看时间轴与日志；失败或想改某一步，点该步「重跑」即可从该步继续（后续步骤会一并重跑）。全程产物落盘在 `_oneshot/<任务号>/`，服务重启后内存任务丢失，但文件仍在。

**文献装配怎么判**：先看这条占位要的是什么，再决定去哪找——

- **要一份数据**（World Bank WDI、ILO、ITU、OECD、国家统计局…）：直接按数据集格式著录（机构 + 年份 + 数据集名 + 链接），**不去检索论文**。以前这类会配成"一篇讨论 WDI 的文章"，现在不会了。
- **点名了某一篇**（"Autor, Levy and Murnane"、"Romano–Wolf (2005)"）：按作者 + 年份精确定位，不按关键词猜。定位不到就**留空**，并写明"请手工补这一条，不要用相近文献顶替"——宁可空着，也不塞一条不相干的。
- **其余**：走 ① OpenAlex 检索 → ② 白名单（正式出版物、有 DOI、年份合理）→ ③ 相关性（核心术语是否命中标题、检索词重合比例）。命中充分记为**强匹配**；只部分命中记为**弱匹配**，照样替换但标出来让你核 DOI；完全不相关则**不替换**，保留 `[CITE: ...]` 并写明原因。

`06_refs.md` 里有「原始占位 → 检索式 → 命中文献 → DOI → 判定」的逐条对照表，判定栏会写清是"机构数据源""点名文献（命中 3/3 个点名的姓）"还是"检索词重合不足"。

著录按所选引用体系生成：IEEE（数字制）、APA 7th、Chicago author-date、GB/T 7714——文内标记与参考文献表都按该体系排版，数字制按首次出现编号、著者-年制按字母序。

**引用格式会对账**：`07_check.md` 里有一节「引用格式」，按对应的 `citation-*.md` 检查卷期写法（`Vol. 51(1)` 应为 `51(1)`）、DOI 形式、作者名合法性（出现 `A, H. D.` 这种单字母姓说明检索源的显示名解析失败）、来源类型（把平台字段当刊名）、以及正文引用与文献表是否双向对应。**题名 sentence case 只提示不自动改**——自动转会把 `China`、`GDP` 一起降成小写，比不改更糟。

**表格、图与公式怎么落地**（很多人卡在这一步，所以单独说）：

- **清单不是摆设**：第 4 步产出的 `tables` / `figures` 清单（编号、标题、所属章节、要展示的内容）会按章节分发到第 5 步的提示词里——写结果章时，提示词里就明确列出「本节必须实际产出的表/图」，并规定写法：表必须是 `**Table N.** 标题` + GFM 表格（至少 2 行），图必须写占位块。
- **表格**：GFM 表格，导出 Word 时转成真表格（真网格、表头加粗、跨页重复表头）。没有数据时单元格写 `[TBD: 要填什么]`，**不留空、不编数字**；数据状态为「无数据」时只给表头与行标签骨架。
- **图**：稿内产出的是**占位块**，不是图片：

  ```
  > **Figure 1.** Event-study estimates
  >
  > Plot type: coefficient plot with 95% CI
  > Required inputs: [TBD: coefficients and SEs by period]
  > Status: [TBD: draw after the data are assembled]
  ```

  为什么不出图：出图要你的真实数据，工具不伪造数据也就不伪造图。占位块把「画什么图、要哪些数据、现在缺什么」写清楚，你补数据时照着画即可。模型漏写图时，第 5 步结束后会按清单自动补占位块（已写的不重复补）。
- **公式**：定量/预测两条线的方法章与结果章强制要求给出模型设定式（`$$ ... $$` 独立成段，编号写在公式内末尾如 `\qquad (1)`）。渲染用完整版 MathJax（`\boldsymbol`、`\operatorname`、`\tag` 等扩展都在），**单个公式出错只降级它自己**，不会连累整篇；导出 Word 时转成**原生可编辑公式（OMML）**，居中显示，`\tag{1}` 会变成 `(1)` 而不是字面量 `tag1`。
- **第 7 步会核对图表对不上**：自检统计稿内真实存在的表/图编号与正文引用，做差集报出「正文引用了稿内不存在的 Table 3」；编号被重复使用（两张 Table 1）也会单独报「重号」——这两个都是导出后才会暴露的硬伤。

**预期**：6000–8000 词英文稿约 5–15 分钟（取决于模型速度），共 10–14 次模型调用（多出的 1 次用于把占位翻译成英文检索式）。产出是**工作稿**，不是可直接投稿的定稿——`[TBD]` 是留给你的数据，弱匹配与残余 `[CITE]` 是留给你核对的。

## 七、能力边界（使用前必读）

1. **不支持纯理论数理类论文**（数学/理论物理/理论经济等"定义-定理-证明"结构）——规则库基于 IMRaD，硬套会系统性误判。
2. **基础科学、临床两条线可信度较低**——规则已建但未做真实全文校验；定量实证、质性研究最可靠（已用 12 篇真实论文逐条核对）。
3. **不覆盖领域表征标准**——ACS Style Guide、IUPAC 命名、晶体学 CIF 等须核对目标期刊作者指南。
4. **词面检测 ≠ 审查结论**——全库 393 条规则中仅 95 条可词面自动判定，其余需大模型判读。本应用两者都做，但大模型判读仍可能有误，重大结论请人工复核。
5. **一键成稿产出的是工作稿**——它保证结构、表达与引用来源可核实，但不会替你有数据、有真实结果；`[TBD]` 必须自己填，弱匹配与残余 `[CITE]` 必须自己核。英文优先，中文通道需按目标刊改写。
6. **文献装配只保证「真实存在且主题相关」**——不等于它就是该论点最合适的出处；引用前务必打开 DOI 看一眼。
7. **数据画像的方法推断是规则判断，不是审稿意见**——它按列名、类型、面板结构猜方法族（DiD/IV/RDD…），猜错会给出不合适的主线建议。建议只在「你没把握」时参考，最终由你决定；采纳后仍可在「① 前置条件检查」里看到冲突提示。

### 关于首页那句宣传语

> 30 余本方法论专著，393 条可核查规则，管得住写法，管不了数据。
> 没有完美的论文，PaperMate 也一样。

这句不是修辞，是口径，数字都能对上：

| 说法 | 出处 | 实际 |
|---|---|---|
| 30 余本方法论专著 | `skill/academic-writing-v1.1/references/book-index.md` | **31 本**专著 + **6 份**报告规范（CONSORT 2025 / STROBE / PRISMA 2020 / STARD 2015 / EQUATOR / ICMJE） |
| 393 条可核查规则 | `rules/rules.yaml` | 393 条，其中 138 条附 `example_bad` / `example_good` |
| 管得住写法 | `detectors.yaml` + 大模型判读 | 95 条可词面判定，其余 298 条需对照 signal 逐条判读 |
| 管不了数据 | — | `[TBD: ...]` 只能你自己填，工具不会编数据 |

对外宣传请沿用「30 余本」与「393 条」这两个数，不要改写成「30 本」或「400 条」；新增规则或书源时，先改 `book-index.md` 再改这句。

## 七点五、报错怎么读（常见三条）

| 现象 | 真实原因 | 怎么办 |

| 点「测试连接」→ **自检失败 / 说明 Method Not Allowed** | 后端还是**旧进程**，里面没有 `/api/llm/test` 这个路由，所以返回 405。与 API 地址、Key 无关 | 关掉那个命令行窗口，重新双击 `start.bat`。页面顶部如果出现红色「后端还是旧版本」提示条，就是同一件事 |

## 十、1.3.0 变更摘要（云部署）

只影响部署形态，不改变任何写作规则、审查判定与文献装配逻辑。

| 项 | 1.2.8 | 1.3.0 |
|---|---|---|
| 监听地址 | 写死 `127.0.0.1` | `PAPERMATE_HOST`，默认仍是 `127.0.0.1` |
| 自动开浏览器 | 总是尝试 | 服务端模式/无 DISPLAY 时跳过 |
| 端口被占 | 自动顺延 | 服务端模式直接报错（反代按固定端口配） |
| 访问控制 | 无 | 可选访问口令 + HttpOnly 签名 Cookie |
| Key 归属 | 服务端统一 | `shared`（共用）/ `byok`（各人自带） |
| 追问会话 | 进程内存 | 落 `_sessions/`，7 天过期，最多 500 条 |
| 成稿任务 | 进程内存 | 每阶段落 `_state.json`，重启变 `interrupted` 可重跑 |
| 数据目录 | `%LOCALAPPDATA%` | 容器 `/data`，裸机 `/var/lib/papermate` |
| 部署产物 | exe / 源码包 | 另加 Dockerfile、docker-compose.yml、systemd unit、Nginx 配置、install.sh |

**两个安全性硬约束**（代码层面拦，不靠前端藏）：

1. `_oneshot/<job>/_state.json` 永不写入 `llm` 字段——容器卷被备份或分享时不会泄露 API Key。
2. `PAPERMATE_ALLOW_SERVER_KEY=0` 时 `resolve_llm()` 完全不读 `.env` 与环境变量，
   只用请求体里的 Key。前端即使被绕过也拿不到公共 Key。

**一条合规硬约束**：AI 产出导出必须带水印警示。

- `/api/export` 收到 `ai_generated: true` 时，`md` / `docx` 在正文前插入警示块，
  `tex` 在导言区前插入 `%%` 注释（不污染排版）。
- 前端本地直接生成的 `md`（不过后端）由 `AI_WATERMARK_MD` 补齐，两边文案须保持一致。
- 新增 AI 产出类结果时，务必把它登记进 `AI_RESULT_KEYS`，否则导出会漏警示。

**升级注意**：桌面版直接覆盖安装即可，数据目录机制未变（仍是
`%LOCALAPPDATA%\PaperMate` + `datahome.txt` 引导）。云部署首次启动会多建
`_sessions/` 目录，无迁移动作。

## 十一、1.3.0 变更摘要（参考文献根治）

1.2.9 的参考文献仍是「先写正文 → 留 `[CITE: 描述]` → 事后检索猜该配哪篇」。
实测一份烟草配方稿件暴露了结构性后果：4 处引用只装上 2 处，且装上的那条
与被引内容毫无关系；另一份稿件 48 处占位装上了 16 处，其中 14 处是弱匹配。

1.3.0 改成**先建库、再写作**（与研墨同思路，但坚持 DOI 可核实）：

| 项 | 1.2.9 | 1.3.0 |
|---|---|---|
| 文献从哪来 | 正文写完后逐条检索 | 成稿前按题目+大纲建 18~48 条**文献库** |
| 正文怎么标 | `[CITE: 这是什么来源]` | 只准标库内编号 `[n]`，库外一律不引 |
| 库里没有合适文献 | — | 写 `[NEEDCITE: 需要什么]`，装配阶段再检索 |
| 越界编号 | 无此概念 | 拦下并标 `[TODOFIX: ...]`，**绝不偷换成相近文献** |
| 单条复用上限 | 无 | 同一篇全文最多引 2 次，超出换下一个候选 |
| 参考文献表 | 列出所有命中 | 只列正文真正引用过的（符合 APA/IEEE） |

同时修掉三个真实缺陷：

1. **主题不符的弱匹配会过线**。「inter-rater reliability sensory panels」曾把
   一篇「胸腰筋膜超声测量」判成匹配——术语命中了，领域完全不同。现在要求
   检索式与标题至少有一个共同**领域词**（剔除方法词后比较）。
2. **中文作者名被拆错**。OpenAlex 返回「任维羡」这种纯中文名时，著录结果
   是 `, 任.`（空名 + 姓）。现在整段作姓，输出 `任维羡`。
3. **正文里印着流水线口吻**。`Plot type:` / `Required inputs:` / `Status:`
   曾被写进正文，读者会看到 "author to choose"。现在正文只留图题，
   画法要点归到稿末「待补图表」清单；老稿件导出时也会被自动清理。

**不在本次范围内**：`[TBD: ...]` 数据占位照旧保留——那是作者必须自己填的
真实数据，系统不会也不能代填。
