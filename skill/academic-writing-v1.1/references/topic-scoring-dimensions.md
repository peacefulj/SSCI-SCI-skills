# 选题评分维度矩阵（6 范式 × 5 层级）

> 本文件定义「AI 三维评估选题」的评分维度标准，移植自研墨平台 v1.10.0 的 `paradigms.js`（`evalFocus` 字段）与 `WQ_LEVELS`（`innovation` 字段）。
> **核心原则**：三维维度名固定（新颖性 / 可行性 / 数据·材料可得性），但每个维度下的**评价关切**随范式与层级变化。

---

## 一、三维度与范式关切（evalFocus）

每个范式对三个维度的关切不同。agent 拼评估提示词时，取用户范式对应的这一整行。

| 范式 id | 范式名 | 新颖性关切 | 可行性关切 | 数据·材料可得性关切 |
|---|---|---|---|---|
| `quant` | 定量实证 | 边际贡献是否清晰、识别策略是否有增量 | 识别策略的可行性、内生性风险是否可控 | 关键变量能否在现有数据库找到、样本区间是否可覆盖 |
| `eng` | 工程技术 | 相对 SOTA 的性能提升空间、创新点可验证性 | 数据集/算力可得性、方法复现性 | 数据集/评测基准是否可得、公开数据集是否够用 |
| `med` | 医学临床 | 临床意义（PICO 是否清晰）、对指南/实践的潜在改变 | 伦理与可行性、样本量是否可实现 | 病例/人群数据可得性、随访与结局数据可获取性 |
| `qual` | 质性研究 | 理论对话对象是否清晰、研究问题的质性适配度 | 田野/样本可得性、研究者身份与进入方式 | 研究对象/场所能否进入、访谈/文本材料可获得性 |
| `basicexp` | 基础科学实验 | 与已有体系的差异点、科学问题的清晰度 | 表征手段可得性、实验方案可控性 | 试剂/样品/表征设备的可得性、发表窗口期 |
| `theory` | 理论·数理 | 问题的数学意义、与已有定理的边界 | 假设的强弱与一般性、证明工具是否在手 | 相关文献/预印本的可得性（注：无"数据"，此项退化为"文献可得性"） |

### 范式完整 evalFocus（供提示词原样引用）

- **quant**：「选题评估侧重：识别策略的可行性与数据可得性、边际贡献是否清晰、内生性风险。」
- **eng**：「选题评估侧重：相对现有方法的性能提升空间、数据集/算力可得性、复现性与创新点可验证性。」
- **med**：「选题评估侧重：临床意义（PICO 是否清晰）、伦理与可行性、样本量、对指南或实践的潜在改变。」
- **qual**：「选题评估侧重：研究问题的质性适配度、田野/样本可得性、理论对话对象是否清晰、研究者身份与进入方式。」
- **basicexp**：「选题评估侧重：科学问题的清晰度、表征手段可得性、与已有体系的差异点、发表窗口期。」
- **theory**：「选题评估侧重：问题的数学意义、假设的强弱与一般性、与已有定理的边界、证明工具是否在手。」

---

## 二、层级与创新标尺（innovation）

层级决定「新颖性」这一维怎么打分。层级越高，对"新颖"的要求越苛刻。

| 层级 id | 层级名 | 创新标尺（决定新颖性打分口径） | 文献规模预期 | 篇幅口径 |
|---|---|---|---|---|
| `bsc` | 本科毕设 | 规范性优先于创新性：结构完整、格式规范、逻辑自洽、可顺利答辩 | 15-30 篇 | 全文约 1-2 万字 |
| `master` | 硕士论文 | 需要「一定创新」：方法/数据/视角至少一点新意，文献综述有深度 | 50-80 篇 | 全文约 3-5 万字 |
| `phd` | 博士论文 | 系统性创新：明确原创贡献，创新点贯穿全文并逐章兑现 | 150 篇以上 | 全文 10 万字+，多章联动 |
| `journal` | 期刊投稿 | 边际贡献明确：相对文献矩阵的增量贡献要能一句话说清 | 以综述需要为准 | 以目标期刊要求为准 |
| `general` | 一般性研究 | 以把问题讲清楚为准：不预设创新标尺，也不按投稿口径苛求 | 以论证需要为准 | 篇幅按需 |

### 层级完整 innovation（供提示词原样引用）

- **bsc**：「规范性优先于创新性：结构完整、格式规范、逻辑自洽、可顺利答辩。」
- **master**：「需要『一定创新』：在方法/数据/视角上至少一点新意，文献综述要有深度。」
- **phd**：「系统性创新：明确的原创贡献，创新点须贯穿全文并逐章兑现。」
- **journal**：「边际贡献明确：相对文献矩阵的增量贡献要能一句话说清。」
- **general**：「以把问题讲清楚为准：重在问题清晰、逻辑完整、证据充分，不预设创新标尺，也不按投稿口径苛求。」

## 三、范式对应章节骨架（选题 → 研究设计衔接用）

选题定了之后进入研究设计，不同范式用不同章节骨架（此处只列骨架，详细审查见 `references/genre-*.md`）：

| 范式 | 章节骨架 |
|---|---|
| quant | 摘要 / 引言 / 文献综述 / 研究假设 / 数据与研究设计 / 实证结果 / 稳健性检验 / 结论与讨论 |
| eng | 摘要 / 引言 / 相关工作 / 方法 / 实验设置 / 结果与分析 / 讨论与局限 / 结论 |
| med | 摘要（结构化）/ 引言 / 对象与方法 / 结果 / 讨论 |
| qual | 摘要 / 引言 / 文献与理论框架 / 研究方法 / 发现（按主题）/ 讨论与结论 |
| basicexp | 摘要 / 引言 / 材料与方法 / 结果 / 讨论 / 结论 |
| theory | 摘要 / 引言 / 预备知识 / 主要结果 / 证明 / 讨论与注记 |

---

## 四、agent 使用指引

1. 先问清用户的 **范式（track）** 与 **层级**。
2. 从"第一节"取范式对应的三维关切，从"第二节"取层级对应的创新标尺。
3. 把这两段 + 用户选题 + 趋势数据，填入 `assets/topic-prompts.md` 的模板骨架，发起 AI 评估。
4. 输出时**三维分开打分**，每维的"理由"必须回扣该范式的关切点（不能所有范式都写"有意思、能做、有数据"）。
