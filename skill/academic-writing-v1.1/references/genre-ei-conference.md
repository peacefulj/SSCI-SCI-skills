# EI / AI 会议论文 Playbook（v0.1）

目标：6–8 页、双栏、双盲。典型目标会：CVPR / NeurIPS / ICML / AAAI / ACL / ICRA 等。

## 核心差异 vs 期刊

- 篇幅受限 → novelty 优先于 completeness
- 双盲 → 正文不出现机构名、项目名、致谢、指向作者主页的链接
- 有 rebuttal → 投稿时就要预判"三个最可能的攻击点"
- 审稿周期短、审稿人 3–4 人 → 开篇 30 秒决定生死

## 篇幅配比（8 页模板，按需缩放）

| 部分 | 页数 | 占比 |
|---|---|---|
| 标题 + 摘要 | 0.5 | 6% |
| 引言 | 1.5 | 19% |
| 相关工作 | 0.75 | 9% |
| 方法 | 2.5 | 31% |
| 实验 | 1.75 | 22% |
| 结论 + 局限性 | 0.5 | 6% |
| 参考文献 | 0.5 | 6% |

## 各章节要点

### 摘要（Abstract）
- 3–4 句：问题 → 现有方法不足 → 本文方法一句话 → 关键结果/提升
- 不用引用、不用未定义缩写、不写"本文提出了一个框架"这类空话

### 引言（Introduction）
- 漏斗结构：背景 → 具体问题 → 现有方法 gap → 本文做法 → 贡献条目
- **贡献条目用加粗 bullet**，3–4 条，每条一句可验证的话
- 结尾必须同时出现：gap 句（However...）+ 本文方法 + 贡献

### 相关工作（Related Work）
- 不按时间罗列，按"方法谱系"分组
- 每段以"与本文最接近的工作"收尾，并点明差异
- 双盲下引用自己先前工作用第三人称

### 方法（Method）
- 先给整体 pipeline 图和符号表
- 每个创新点一个 subsection，配公式或算法
- 关键设计决策要写"为什么这样选"（为 ablation 埋伏笔）

### 实验（Experiments）
- 基线必须含 SOTA 和简单基线（simple baseline）
- 主结果表 + 消融表 + 定性/误差分析
- 复现细节（超参、硬件、随机种子）放附录或补充材料

### 结论与局限性
- 一句结论 + 2–3 条局限性（审稿人喜欢看到自认局限）

## Rebuttal 结构（返修时）

对每个审稿人：感谢 → 逐条引用并回应 → 标"已改，见 L123"或"不采纳 + 理由"

回应用词模板：
- 同意且已改：We agree and have revised...（见新稿 Lxx）
- 有分歧：We respectfully disagree because... + 证据
- 超出范围：This is out of scope; we focused on...

## 双盲自查清单

- [ ] 正文无机构名、项目号、基金
- [ ] 无 "our prior work [1]"（改用第三人称）
- [ ] 无致谢、无作者主页链接
- [ ] 补充材料匿名
- [ ] 代码仓库用匿名链接

## 投稿前拒稿风险自检（Zobel 3e, ch.5 "Getting It Wrong"）

审稿人常在**开篇几分钟**就形成拒稿判断。五大类硬伤：

| 类别 | 现象 | 自检问题 |
|---|---|---|
| **Irrelevance 无关** | 读两分钟说不清研究问题与贡献 | 引言末段有单一 research question + contribution 清单吗？ |
| **Inadequacy 不足** | 实验 trivial、无文献综述、数据来源不明 | 实验充分支持 claims 吗？数据来源/规模写清了吗？ |
| **Incomprehensibility 不可读** | 摘要/引言语无伦次、堆砌术语 | 摘要一句能读懂吗？ |
| **Ugliness 丑陋** | 图表粗糙、字体混乱、错误密布 | 用官方模板了吗？图表专业吗？ |
| **Ignorance 无知** | 花篇幅讲常识、忽略关键文献、断言错误 | 漏了标题搜索就能找到的关键工作吗？ |

## 贡献的双重标准（Zobel 3e, ch.3）

一篇论文被接受，贡献必须同时具备：

1. **原创性 originality** —— 新、重要、有趣
2. **有效性 validity** —— 可被他人验证的正确性证明（proof / analysis / experiment 至少其一）

只新不验、或只验不新，都会被拒。投稿前自问：删掉所有模型，这篇论文的"新"和"对"分别在哪里？

## 实验公平性底线（Zobel 3e, ch.14）

- 观察（调参）与确认（验证）数据集必须分离，禁止数据泄漏
- 结论须基于多个真正独立的数据集
- 多指标统一报告，禁止挑报有利指标
- 与 SOTA 和简单基线都要比，比较设置须公平
- 异常结果、负结果必须报告，不得隐瞒
- 代码与数据应可公开复现
