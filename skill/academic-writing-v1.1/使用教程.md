## 一、这个技能是什么、不是什么

### 是什么

一套**规则驱动的学术论文写作决策 + 审查知识库**。核心是一条条可判定的规则，每条规则都包含：

- 触发信号（`signal`）—— 什么文字/结构特征会触发这条规则
- 修改方法（`fix`）—— 具体怎么改
- 出处（`source`）—— 来自哪本书、哪一章、哪一页
- 正反例句（`example_bad` / `example_good`）—— 什么算对、什么算错

它不是"会写论文的通用 LLM"，而是给 agent 提供**有据可查、可追溯、可判定**的写作规范。agent 拿到稿件后，不是凭感觉挑毛病，而是逐条对照规则库给结论。

### 支持什么（七条学科主线）

| 主线 | track | 支持度 | 说明 |
|---|---|---|---|
| 工程 / AI（会议+期刊） | `ei-conf` `ai-conf` | ✅ 完整 | 113 条 |
| 定量实证（经济/管理/金融/社会学定量） | `quant` | ✅ 完整 | 56 条 + 共用，**已用 12 篇真实论文全文校验** |
| 预测建模 / 数据科学 | `predictive` | ✅ 完整 | 25 + 16（报告层） |
| 质性研究（案例/现象学/扎根理论/民族志） | `qualitative` | ✅ 完整 | 41 条，**已用真实论文校验** |
| 博士大论文 | `dissertation` | ✅ 完整 | 15 + 共用 |
| 基础科学实验 | `basic-science` | ⚪ 次要 | 24 条，未做真实全文校验 |
| 临床与医学 | `clinical` | ⚪ 次要 | 32 条，未做真实全文校验 |

### 不支持什么（重要，别硬套）

- **纯理论数理论文**（数学 / 理论物理 / 理论经济，`definition–theorem–proof` 结构）：明确不支持。因为规则库的章节枚举基于 IMRaD（摘要/引言/方法/结果/讨论），理论文章没有"实验""结果"章节，硬套会问出"你的消融实验呢"这种错问题。遇到此类稿件应直接告知用户不支持。

## 二、安装与目录结构

把 tar.gz 解压到任意目录即可，无需安装任何依赖（脚本只用 Python 标准库 + `yaml`，若缺 `pyyaml` 需 `pip install pyyaml`）：

```bash
tar -xzf academic-writing-skill-1.2.0.tar.gz
cd academic-writing-v1.1
python -c "import yaml; print('ok')"   # 验证 pyyaml 已装
```

## 三、核心概念：规则四元组

这是理解整个技能的关键。`rules/rules.yaml` 里每条规则长这样：

```yaml
- id: QNT-IDF-001              # 唯一编号：前缀=学科，后缀=序号
  genre: [ssci, sci-journal]   # 适用体裁
  track: quant                 # 学科主线
  section: method              # 属于论文哪个章节
  rule: 必须明确说明识别策略（如工具变量/断点/双重差分/固定效应）
  signal: 方法章只描述数据与回归，未出现"识别/内生性/工具变量/DiD/RDD"等词
  fix: 补一段"识别策略"，说明内生性来源 + 用什么方法解决 + 为什么有效
  source: Angrist & Pischke, Mostly Harmless Econometrics, ch.3
  severity: must               # 硬伤/建议/可选 三级
  example_bad: "我们用 OLS 估计了政策对收入的影响。"
  example_good: "政策是否外生存疑（地方可能根据经济状况选择性实施），故以政策发布时间构造断点，用 RDD 识别局部平均处理效应。"
```

四个关键字段：

1. **`signal`（触发信号）**：什么情况下这条规则"该被提醒"。这是 agent 判断"要不要提这条"的依据。
2. **`fix`（改法）**：给出具体、可操作的修改方向，而不是"注意逻辑清晰"这种空话。
3. **`source`（出处）**：追溯到具体书籍章节。这是规则权威性的来源，也是 agent 答复用户"为什么这么说"的依据。
4. **`severity`（严重度）**：`must`（硬伤，会被拒）/ `should`（建议，会被要求大修）/ `nice`（可选，优良实践）。

> **为什么这样设计**：一条没有出处、没有触发条件的"建议"在 agent 里是没法用的——模型会乱套用。有了 signal 和 source，agent 才能"该提的提、不该提的不提、提了有据"。

## 四、快速上手：审查一篇论文

假设你有一篇定量实证论文草稿 `manuscript.md`，想查问题。

### 第 1 步：结构自检（快）

```bash
python scripts/check_structure.py manuscript.md --genre quant
```

输出会告诉你：必需章节缺哪些、识别策略写了没、gap 句和贡献声明有没有。

### 第 2 步：逐条打分（细）

```bash
python scripts/score.py manuscript.md --track quant
```

典型输出：

```
=== manuscript.md | track=quant ===
  词数 5200 / 汉字 0 | 适用规则 56 | 自动检查 30 | 需人工 26
  命中 5 处（硬伤 2 / 建议 0 / 可选 3）：
    [硬伤] QNT-IDF-001  (缺失必需要素)
    [硬伤] QNT-RPT-001  (缺失必需要素)
    ...
  不适用 17 条（前提情境未出现）
```

### 第 3 步：结合规则库人工复核

脚本命中的只是"词面能判定"的部分（95 条有检测器），其余 298 条需要 agent 对照 `rules.yaml` 的 `signal` 人工核对。**千万别把脚本输出直接当成"已通过审查"**——脚本只负责筛出可疑项，最终结论要由 agent 逐条判读。

## 五、五大使用场景

### 场景 0：选题雷达（v1.3.0 新增，OpenAlex 趋势 + AI 三维评估）

这是"做什么方向 / 值不值得做"阶段的能力，移植自研墨平台。三步走：

**① 定范式与层级**：确认用户属于哪个学科主线（`quant`/`eng`/`clinical`/`qualitative`/`basic-science`）与层级（本科/硕士/博士/期刊/一般研究）。

**② 跑 OpenAlex 全球发文趋势**：

```bash
python scripts/topic_radar.py "mobile money rural entrepreneurship"
```

输出逐年发文量柱状图 + 增长率判读。三档阈值：**>20% 快速升温 / −20%~20% 平稳 / <−20% 热度回落**。注意：OpenAlex 是英文库，中文主题要先转英文检索词；样本量偏小（<10 篇）时增长率会失真，脚本会自动提示。

**③ AI 三维评估**：按 `assets/topic-prompts.md` 的模板拼装提示词（通用骨架 + 范式 evalFocus + 层级 innovation 标尺 + 真实趋势数据），产出：

- 三个候选题目（每题一句话说角度+创新点）
- 每题三维打分（新颖性/可行性/数据·材料可得性，各 1-10 分）
- 数据与文献可得性清单
- 主要风险与规避建议（2-3 条）

**关键机制**：三维维度名固定，但每维的评价标准随范式/层级变——如 quant 的"可行性"看识别策略+内生性，qual 的"可行性"看田野/样本可得性，本科的"新颖性"只要求规范，博士的"新颖性"要求系统性创新。完整标准在 `references/topic-scoring-dimensions.md`。

**目标期刊/会议**：`assets/target-venues.yaml` 有 6 范式各一份清单（含中英文、CCF/SCI/SSCI 分区标注），agent 据此引导用户下拉选择，用户也可自定义。

### 场景 1：选题（"做什么方向、值不值得做"）

同上"场景 0"的选题雷达，产出研究问题 + gap 论证。gap 论证必须同时说清三件事：现有文献做了什么、缺什么、为什么现在能做（对应规则 `WRI-INT-002`）。

### 场景 2：研究设计（"这样设计行不行"）

按 track 校验设计，例如定量实证查：
- 识别策略是否成立（内生性来源、工具变量的排他性与相关性、断点的操纵检验）
- 抽样与样本量、对照组设置
- 数据来源是否可复现

### 场景 3：初稿写作（"帮我写引言/方法/结果/讨论"）

读 `references/section-introduction.md`、`section-methods.md`、`section-results.md`、`section-discussion.md`，逐段生成引导。每条规则自带 `example_bad/example_good`，可直接作为改写范例。

### 场景 4：修改审查（"帮我看看、改得怎么样"）

这是本技能最成熟的场景，完整流程：

1. 定 track → 2. 定 genre → 3. 跑 `check_structure.py` 看结构 → 4. 跑 `score.py` 看规则命中 → 5. 逐条对照 `rules.yaml` 人工复核 → 6. 按严重度输出三层风险清单（见 SKILL.md 第五步）。

### 场景 5：投稿与返修（"要准备什么、怎么回审稿意见"）

- 投稿：产出投稿包清单（cover letter、标题页、图表、伦理声明、数据可用性声明、报告规范清单）。
- 临床类：读 `references/reporting-guidelines.md` 选对报告规范（CONSORT 用于随机试验、STROBE 用于观察性研究、PRISMA 用于系统综述、STARD 用于诊断准确性研究）。
- 返修：产出 rebuttal 结构（逐条回应 + 改动定位 + 不改的理由）。

## 六、两个脚本的完整用法

### `check_structure.py` —— 结构自检

```bash
python scripts/check_structure.py <稿件路径> [--genre 体裁] [--lang auto|en|zh]
```

- `--genre` 可选值：`ei-conf | ai-conf | sci-journal | ssci | dissertation | quant | predictive | qualitative | basic-science | clinical`
- `--lang`：`auto`（默认，自动判断中英）/ `en` / `zh`

**用途**：快速看章节完整性、关键词面项（识别策略、编码方法、报告规范、伦理等）。**特点**：快，但只覆盖"能词面化"的条目。

### `score.py` —— 批量打分

```bash
# 单个稿件
python scripts/score.py manuscript.txt --track quant

# 批量跑一个目录（配 manifest 清单）
python scripts/score.py --suite tests/samples --manifest tests/manifest.yaml

# 导出 JSON 结果
python scripts/score.py --suite tests/real --manifest tests/manifest_real.yaml --json out.json
```

- `--track` 可选值：`quant | predictive | qualitative | basic-science | clinical | reporting | ei-conf | ai-conf | sci-journal | ssci | dissertation`

**输出字段含义**：
- `适用规则 N`：该 track 下共多少条规则
- `自动检查 N`：其中多少条有词面检测器，脚本能自动判定
- `需人工 N`：剩下需要 agent 人工对照 signal 判定的数量
- `命中 N 处`：按 severity 分成硬伤/建议/可选三档
- `不适用 N 条`：规则的前提情境在文中没出现（如没做 PSM，就不查共同支撑）

**关键提醒**：脚本会自动在正文后半段最后一次 References 标题处截断，避免文献题名污染判定（否则参考文献里的 "case study" 会让一篇非案例研究被误判）。

## 七、引用格式（四套）怎么选

`assets/` 下有四套引用格式，**一套稿件只用一套**，按学科与投稿语言选：

| 你的情况 | 用哪个文件 |
|---|---|
| 工程（计算机/电子/机械/土木），投 IEEE 会议或期刊 | `citation-ieee.md` |
| 心理/教育/管理/社会学，投 SSCI 或 APA 系期刊 | `citation-apa.md` |
| 中文期刊、中文学位论文、国内会议 | `citation-gb7714.md` |
| 人文、历史、部分社科（脚注制） | `citation-quickref.md` |

最常见的错误（CIT-STY-001）：正文用 `[1]` 编号，文末却按字母序排列——这是中英混排。规则库 CIT 族共 16 条，覆盖体系一致性、IEEE 编号顺序、APA 第 7 版变化（去出版地、DOI 加 https）、GB/T 7714 文献类型标识与引用日期。

## 八、如何二次开发

### 8.1 加一本书 → 产出新规则

遵循 "book-to-skill 五步法"，模板见 `references/conversion-template.md`：

1. **可判定性测试**：书里这句话能不能变成"看到 X 就提醒 Y"？不能判定的（如"文笔要优美"）丢弃。
2. **归类**：归到哪个 `genre`（体裁）、`track`（学科线）、`section`（章节）。
3. **写 signal**：什么文字特征触发。
4. **写 fix**：具体改法。
5. **写元数据**：`source`（书+章节+页码）、`example_bad/example_good`、`severity`、`conflict`（与其他规则冲突时标注）。

### 8.2 新规则是否要配检测器

- 规则能被**正则表达式**可靠判定 → 加检测器到 `rules/detectors.yaml`。
- 规则需要**语境判断**（如"是否存在异质性来源""工具是否需要声明单调性"）→ 不要配检测器，留给 agent 人工核对。配了检测器反而会误报。

检测器四类语义：
- `require`：出现某词面，必须同时出现另一类词面（缺了才报）
- `forbid`：出现某词面即报
- `require_when` / `forbid_when`：前提情境（`when`）出现时，才要求/禁止某词面
- `not_when`：排除情境（如 DiD 的交互项就不该被要求做简单斜率）

### 8.3 回归验证（改完必须跑）

```bash
python scripts/score.py --suite tests/samples --manifest tests/manifest.yaml
python scripts/score.py --suite tests/real --manifest tests/manifest_real.yaml
```

- 构造样稿 39 份应全部落在预期区间（好 0–1 / 中 3–7 / 坏 7+）
- 真实论文 12 篇应稳定在平均 4.9 处命中、1.5 处硬伤附近；若大幅偏离，先怀疑自己改出了误报

## 九、常见问题与避坑

### Q1：脚本报了 5 处硬伤，是不是论文很烂？

**先怀疑自己判读有误。** 已发表论文平均 1.5 处硬伤；如果一篇正常论文被你报出 5 处硬伤，大概率是检测器误报或语境没看全。

### Q2：为什么有些规则脚本从来不触发？

历史上有过 30 处检测器的短缩写正则（`\bDiD\b` 等）因转义写坏而形同虚设。写检测器时，短缩写必须用大小写敏感模式 `(?-i:\bDiD\b)`，否则 `\bDiD\b` 忽略大小写会命中 "did"。**凡含反斜杠的内容，一律用 Write/Edit 工具写，不要用 shell heredoc**（heredoc 会把 `\\b` 写成 `//b`）。

### Q3：基础科学、临床两条线能用吗？

能用，但**可信度低**——这两条线规则已建，但没做过真实全文校验。给用户下结论时要说清楚这点。定量实证和质性研究两条线最可靠（12 篇真实论文逐条核对过）。

### Q4：遇到纯数学/理论物理论文怎么办？

明确告知用户**不支持**，不要硬套。原因是章节枚举基于 IMRaD，理论文章没有"实验/结果"章节，硬套会系统性误判。

### Q5：领域表征标准（ACS/IUPAC/晶体学 CIF）问到了怎么办？

规则库**不覆盖**这些领域标准。应提示用户核对目标期刊作者指南，不要凭记忆编。
